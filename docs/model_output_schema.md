# Model Output Schema

<!-- MODEL_OUTPUT_SCHEMA_OK -->

## Purpose

This document describes the model output schema for the lightweight multi-head image forensics prototype.

The schema defines the structure of the final forensic report produced by inference. It is implemented as a pure-Python schema and dry-run helper module (`src/cv_forensics/model_output_schema.py`) with no real model inference, training, image loading, or dataset access.

This is a **schema and dry-run helper task**, not real inference or training. The example files under `configs/` are illustrative only.

---

## Mapping to Proposal Target Outputs

The project (see `docs/project_brief.md` Section 5) defines four target outputs:

| Proposal output | Schema field(s) |
|---|---|
| **Class** | `class`, `class_conf` |
| **Mask** | `localization_head`, `mask_area_pct`, `mask_ref` |
| **Family** | `family`, `family_conf` |
| **Reason** | `reason`, `evidence` |

### Required fields

| Field | Type | Description |
|---|---|---|
| `schema_version` | string | Schema version string (e.g. `"0.1.0"`) |
| `class` | string | Predicted class: `real`, `synthetic`, or `tampered` |
| `class_conf` | object | Confidence over all three class labels (sums to ~1.0) |
| `family` | string | Coarse generator-family provenance (see below) |
| `family_conf` | object | Confidence over known family labels (sums to ~1.0) |
| `localization_head` | string | Localization state (see below) |
| `mask_area_pct` | number or null | Percentage of image area flagged (0–100), null if not activated |
| `threshold_tau` | number | Conditional localization threshold |
| `tampered_score` | number | Tampered class probability (0–1) |
| `evidence` | array | List of evidence signal objects |
| `perturbations` | array | List of perturbation tags applied |
| `reason` | string | Template-based Korean explanation |

### Optional fields

`mask_ref`, `visualization_ref`, `model_stage`, `family_policy`, `latency_ms`, `fps`

Optional reference fields must not contain real local paths, protected paths, network URLs, or secrets. Placeholder strings such as `<MASK_NOT_MATERIALIZED>` are allowed.

## Conditional Localization Rule

The inference flow runs as follows:

1. Shared visual backbone extracts features.
2. 3-way classification head and generator-family provenance head run unconditionally.
3. If `tampered_score >= threshold_tau`, the conditional localization head is activated.
4. If `tampered_score < threshold_tau`, localization is skipped to save computation.

### Localization states

| State | Meaning |
|---|---|
| `activated` | Localization head ran; `mask_area_pct` is populated |
| `skipped_below_threshold` | `tampered_score` was below `tau`; localization skipped |
| `not_applicable` | Class is `real` or `synthetic`; localization does not apply |
| `unavailable` | Localization head is not present at this model stage |

The schema preserves both `tampered_score` and `threshold_tau` so that false-negative behavior can be analyzed post-hoc (i.e. cases where the tampered image was classified correctly but localization was not activated due to a high tau).

## Coarse Family-Level Provenance

The `family` field represents **coarse generator-family provenance**, not exact model attribution.

Initial family label candidates:

- `LatDiff` — latent diffusion family
- `PixDiff` — pixel-space diffusion family
- `GAN` — GAN-based generator family
- `Other` — other or unknown generator family
- `Real-or-N/A` — real image or family label not applicable

The explanation templates always phrase family as an *estimate*, not a definitive attribution.

---

## Template-Based Explanation

The `reason` field is generated by `src/cv_forensics/explanation_templates.py` using:

- Class label and confidence
- Family label and confidence
- Localization state and mask area
- Perturbation tags

No LLM or free-form generation is used. All templates are deterministic and produce short Korean strings. Family is described as a coarse estimate. Localization activation is explained when it did not run.

See `configs/explanation_templates.example.json` for template IDs and placeholder documentation.

---

## Social-Media Perturbation Tags

The `perturbations` field lists the perturbation types applied to the image:

`none`, `jpeg`, `resize`, `crop`, `rotation`, `padding`, `shear`, `screenshot`, `text_overlay`, `sticker_overlay`, `recompression_chain`

This supports future perturbation robustness analysis (Delta F1, Delta IoU) as described in `docs/project_brief.md` Section 7.

## Evidence Signal IDs

| Signal ID | Description |
|---|---|
| `global_synthetic_artifact` | Global GAN/diffusion artifact pattern |
| `boundary_discontinuity` | Local boundary discontinuity |
| `texture_inconsistency` | Texture inconsistency |
| `local_mask_activation` | Localization mask activation |
| `provenance_family_signal` | Generator-family provenance signal |
| `low_confidence` | Low classification confidence |
| `social_media_recompression` | Social-media JPEG recompression artifact |
| `screenshot_padding` | Screenshot-like padding artifact |
| `text_overlay_occlusion` | Text overlay occlusion |
| `sticker_overlay_occlusion` | Sticker overlay occlusion |
